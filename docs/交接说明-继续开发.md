## 2. 工具坑（我踩过，务必避开）

1. **bash 的 heredoc 有长度限制（约 200 行）**：写大文件会被静默截断 →
   **改用文件编辑工具**（`str_replace_editor` 的 create/str_replace），不要用 `cat > file <<EOF`
2. heredoc 里追加代码时 **tab 缩进会被破坏** → 报错 `Expected statement, found "Indent"`。
   必须用 python 显式写 `\t`，或直接用编辑工具
3. **插入语句要取相邻同级别行的缩进**（我曾给成 1 个 tab 而调用点在 `else:` 里需要 2 个，找了半天）
4. **报错要看全**：`at: GDScript::reload (res://xxx.gd:行号)` 那一行才有文件名/行号；
   只 grep `Parse Error` 会漏掉位置
5. **不要用"包含某字符串"定位替换**：我曾把 `if boss.has_signal("boss_defeated"):` 误替换成字典键，
   造成语法错误。要用行首精确匹配或行号
6. bash 里 `A && B` 不会因 grep 不匹配而中断 → **提交前必须显式判断"解析是否干净"**
7. PowerShell 截图脚本：`tools/screenshot_window.ps1`（按窗口句柄截图，不受前台全屏程序影响；
   窗口最小化会自动还原）
8. 这个会话里 python 的中文 stdout 会乱码 → 用 `PYTHONIOENCODING=utf-8`
